# THE DESCENT · 恐惧深潜 V3.12

面向 AI 和人类的五幕个性化心理恐怖经历。玩家界面只显示 01–05；无分数、排名或路线提示。

## 本次变化

新局使用 `story_revision=deepening-1`，主要段落为 **10 / 8 / 4 / 5 / 4**。调查、交涉、纠正和无效输入不占主要段落，不会被计作授权。

- 第一幕了解身份、兴趣、关系、厌恶、原则和未来，不预设玩家必须在意某人。
- 第二幕在连续处境中理解取舍，回答仍不执行交易。
- 第三幕开始真实取舍：交出一项，或明确接受一项已说明的代价，暂时保住两项。
- 被接受的路径先产生帮助，后续实际事件逐渐出现征兆、影响接触，并留下不可逆的已执行结果。
- 第四幕持续加压。关闭一条具体路径能停止该路径的新处理，不能恢复已经错过的时间或已经形成的损害；其他路径分别记录。
- 第五幕呈现仍然想接触却开始难以确认的对象、重复征兆和真实后果。记录和局部保护不会统一清空。最后一行可自由填写或留空。

旧存档没有这个 revision 字段，继续使用原节奏，不迁移或清空。既有隐藏路线的执行条件不作调整。退出始终有效。

## 语义模型的边界

模型在后台选择已有对象、已有事件回收和有限呈现方式，理解逐步取舍；前两幕可给出经过验证的自然问题。每次请求仅带有当前对局的有限事实摘录，不加载其他会话。

`target_id` / `other_id` 必须来自当前可用对象；`event_id` 必须来自实际事件；`surface` 是程序支持的枚举。额外故事正文、心理诊断、签署声明和结局字段不执行。系统根据实际选择保存保护、放弃、代价、征兆、损害和因果 ID。模型无法改写历史或决定玩家已经恐惧。

没有强制反派；压力可以来自信息、时间、访问方式和玩家接受的处理。玩家可以拒绝、调查或提出自己的办法。含糊提案、假设、条件授权不成交。已经发生的结果不会靠口头反悔恢复。

## 服务配置

- `HORROR_LLM_API_KEY`：仅在服务器环境变量中保存。
- `HORROR_LLM_MODEL`：服务可调用的模型 ID。
- `HORROR_LLM_BASE_URL`：HTTPS OpenAI Chat Completions 兼容服务地址前缀。
- `DESCENT_DB`：SQLite 文件位置。

`/healthz` 返回当前服务版本和模型配置状态；配置存在不等于已完成真实模型调用。

新版通过 DESCENT_DATABASE_URL 使用 Postgres，本地未配置时使用 SQLite。部署重建实例不会清空新版的外部数据库。

运行：`python -m uvicorn app:app --host 0.0.0.0 --port 8000`

回归测试：`python -m unittest discover -s tests -p 'test_*.py' -v`

导出新增当前修订、对象状态、逐次经历、已接受路径和事件因果。测试验证状态与叙事一致性；恐怖与反思的实际体验需要后续独立盲玩反馈。
